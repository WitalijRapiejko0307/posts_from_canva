# План действий: подготовка текста каруселей из Google Doc

**Дата документа:** 15.09.26

Повторяемый цикл: взять **5 постов** выше маркера `🟢 STOP 🟢`, уникализировать их под 8-слайдовые карусели, записать в JSON и сдвинуть маркер. Следующий этап — [`plan-sozdaniya-karuseli.md`](plan-sozdaniya-karuseli.md).

---

## Входные данные

| Что | Значение |
|-----|----------|
| Документ | Google Doc **Text for carousel** |
| ID | `1WkjF2NtZGwx0ThzfoTtKg64bZfe33PSJHkBscxDHPEs` |
| Маркер | `🟢 STOP 🟢` |
| Сколько постов за цикл | **5** сразу над маркером |
| Куда писать слайды | [`material/carousel.json`](../material/carousel.json) |
| Куда писать описания | [`material/description.json`](../material/description.json) |
| Аккаунт в CTA | `@vitali_rapeika` |

**Как выглядит пост в документе:** цепляющий заголовок → тело → призыв подписаться / написать комментарий / сохранить.

---

## 1. Открыть документ

1. MCP `user-chrome-devtools`: `list_pages`.
2. Если вкладка документа уже открыта — `select_page` и вывести её на передний план.
3. Если нет — `navigate_page` на:
   `https://docs.google.com/document/d/1WkjF2NtZGwx0ThzfoTtKg64bZfe33PSJHkBscxDHPEs/edit`
4. Браузер уже открыт в рабочей папке проекта — новую сессию Chrome не поднимать.

Полный текст через DOM (`innerText`) **не читается**: редактор Docs не отдаёт тело документа. Читать содержимое через Google Drive MCP:

```
read_file_content  fileId: 1WkjF2NtZGwx0ThzfoTtKg64bZfe33PSJHkBscxDHPEs
```

---

## 2. Найти маркер STOP

1. В тексте файла найти ровно `🟢 STOP 🟢` (один экземпляр).
2. Если эмодзи в выгрузке Drive «ломается» (`ðŸŸ¢ STOP ðŸŸ¢`) — нормализовать и искать по `STOP`, сверяя соседние строки.
3. Рабочая зона цикла — **только текст выше маркера**. Посты ниже STOP не трогать.

---

## 3. Выделить пять постов выше маркера

Идти **снизу вверх** от STOP и взять пять цельных постов. Границы поста:

- **старт:** заголовок-крючок (часто отдельная строка или жирный абзац);
- **финиш:** CTA — «подпишись», «напиши в комментариях», «сохрани», `@vitali_rapeika`.

Порядок в JSON — **сверху вниз** по документу:

| id | Где в пятёрке |
|----|----------------|
| 1 | самый верхний из пяти |
| 5 | ближайший к STOP |

Черновики, стихи без CTA, обрывки и посты без заголовка в пятёрку не брать.

---

## 4. Уникализировать каждый пост под карусель

На каждый пост — **8 слайдов**, без нумерации (`1.`, `2.` и т.п. в тексте слайдов нет).

| Слайд | Что писать |
|-------|------------|
| 1 | Уникализированный заголовок-крючок (можно КАПС + подзаголовок с новой строки) |
| 2–7 | Короткий подзаголовок + абзац. Смысл поста сохранить, формулировки — новые |
| 8 | Закрытие мысли + призыв подписаться на `@vitali_rapeika`. Тема CTA должна совпадать с постом |

Тон — как в текущем `carousel.json`: жёстко, конкретно, без канцелярита.

**Описание поста** (Instagram caption) — отдельный текст, **не длиннее 300 символов**, тоже уникализированный. В конце — подписка на `@vitali_rapeika`.

---

## 5. Записать слайды в `carousel.json`

1. Открыть [`material/carousel.json`](../material/carousel.json).
2. **Удалить все текущие записи** в массиве `carousels`.
3. Внести пять каруселей в той же структуре:

```json
{
  "carousels": [
    {
      "id": 1,
      "slides": [
        { "slide_number": 1, "text": "..." },
        { "slide_number": 2, "text": "Подзаголовок\nАбзац..." }
      ]
    }
  ]
}
```

- `id`: 1…5  
- у каждой карусели ровно 8 объектов в `slides`  
- `slide_number`: 1…8  
- переносы внутри слайда — `\n`

---

## 6. Записать описания в `description.json`

1. Открыть [`material/description.json`](../material/description.json).
2. **Удалить все текущие записи** в массиве `descriptions`.
3. Внести пять описаний в той же структуре:

```json
{
  "descriptions": [
    { "id": 1, "text": "..." }
  ]
}
```

`id` описания = `id` карусели. Длина `text` ≤ 300 символов.

---

## 7. Перенести STOP на пять постов вверх

После записи JSON маркер должен стоять **над** только что разобранной пятёркой: эти посты считаются обработанными, следующая пятёрка — снова сразу над STOP.

**Как двигать в Google Docs (chrome-devtools):**

1. `Control+F` → найти `🟢 STOP 🟢` (должно быть **1 of 1**).
2. Вырезать только эту строку (`Home` → `Shift+End` → `Control+X`). Не использовать `Control+A`.
3. Найти заголовок верхнего из пяти постов (уникальная фраза).
4. Курсор в начало этого заголовка → `Enter` → вставить маркер.
5. **Не вставлять через `Control+V`**, если буфер мог затереться (поиск Docs / fill перезаписывают clipboard). Надёжнее набрать `🟢 STOP 🟢` через `type_text` на пустой строке над заголовком.
6. `Control+H` с regex **не использовать для `\n`**: Docs часто вставляет литералы `\n\n` вместо абзаца.

Проверка после сохранения Docs (`read_file_content` ещё раз):

- маркер один;
- над ним — ещё не разобранные посты;
- сразу под ним — пост id 1 этой пятёрки;
- в старом месте (перед следующим необработанным «хвостом») маркера нет.

## 8. Проверки перед следующим этапом

- [ ] Найден ровно один `🟢 STOP 🟢`
- [ ] Взяты 5 цельных постов выше маркера, не ниже
- [ ] У каждой карусели 8 слайдов, нумерации пунктов в тексте нет
- [ ] Слайд 8 содержит подписку на `@vitali_rapeika`
- [ ] `carousel.json` содержит только эту пятёрку (старые записи удалены)
- [ ] `description.json` — 5 текстов, каждый ≤ 300 символов, `id` совпадают
- [ ] STOP перенесён на 5 постов вверх, абзац перед первым постом чистый (без `2. Найди…` и без `\n\n`)

## Грабли

| Проблема | Что делать |
|----------|------------|
| Docs не отдаёт текст через `innerText` | Читать через Drive `read_file_content` |
| `Control+V` вставил чужой фрагмент | Не полагаться на clipboard; `type_text` на пустой строке |
| Regex-замена `\n` дала символы `\n\n` | Удалить литералы, разорвать абзац клавишей `Enter` |
| Два маркера STOP | Оставить один, над верхним постом пятёрки |
| Пост без CTA рядом с STOP | Не считать постом; взять соседний цельный блок с заголовком и финалом |
